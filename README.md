# 🚕 Taxi Fleet Tracker

Εφαρμογή για στόλο ταξί: καταχώρηση βαρδιών από το κινητό, αυτόματος υπολογισμός ΦΠΑ,
καθαρό ταμείο, στατιστικά απόδοσης, εξαγωγή για τον λογιστή και ενημέρωση οδηγών μέσω WhatsApp.

- **Next.js 16** (App Router, TypeScript) — mobile-first: στο κινητό η φόρμα είναι πάνω από τα στατιστικά.
- **Supabase** — Authentication (email/κωδικός) και PostgreSQL με **Row Level Security**.
- Δύο ρόλοι:

| | Admin (ιδιοκτήτης) | Οδηγός |
|---|---|---|
| Βάρδιες | όλων των οδηγών | **μόνο τις δικές του** |
| Καταχώρηση βάρδιας | για οποιονδήποτε οδηγό | μόνο για τον εαυτό του |
| Διόρθωση/διαγραφή βάρδιας | πάντα | μόνο δικές του, μέσα σε 24 ώρες |
| Στατιστικά / ΦΠΑ / Ταμείο | συνολικά & ανά οδηγό | μόνο των δικών του βαρδιών |
| Υποδομή Στόλου, WhatsApp | ✔ | ✘ |
| Εξαγωγή Excel (CSV) | ✔ (τα φιλτραρισμένα) | ✔ (μόνο τα δικά του) |

Η απομόνωση των δεδομένων γίνεται **μέσα στη βάση** (RLS): ισχύει ακόμη κι αν κάποιος καλέσει
απευθείας το API του Supabase με το δικό του λογαριασμό.

## Λογιστικοί κανόνες

Οι ίδιοι τύποι υπάρχουν στον κώδικα (`lib/accounting.ts`, για τη ζωντανή προεπισκόπηση της φόρμας)
και **μέσα στη βάση** ως υπολογιζόμενες στήλες του πίνακα `shifts` — η βάση είναι η πηγή της αλήθειας
και ο ΦΠΑ δεν μπορεί να γραφτεί χειροκίνητα.

| Μέγεθος | Τύπος |
|---|---|
| ΦΠΑ εσόδων 13% | `round(Καθαρά × 0.129933, 2)` — π.χ. 160,39 € → **20,84 €** |
| Μικτή είσπραξη (τζίρος) | Καθαρά + ΦΠΑ 13% + Φιλοδωρήματα/Άλλα έσοδα (χωρίς ΦΠΑ) |
| Σύνολο εξόδων | Καύσιμα + Άλλες δαπάνες + Επισκευές/Συντήρηση (μικτά ποσά) |
| ΦΠΑ εξόδων 24% (εμπεριεχόμενος) | `round(Σύνολο εξόδων / 1.24 × 0.24, 2)` |
| Προς απόδοση ΦΠΑ | ΦΠΑ 13% − ΦΠΑ εξόδων 24% → θετικό = **Χρεωστικό**, αρνητικό = **Πιστωτικό** |
| Καθαρό ταμείο (τσέπη) | (Καθαρά + ΦΠΑ 13% + Φιλοδωρήματα) − Σύνολο εξόδων |
| Συνολικά χλμ | Μισθωμένα + Ελεύθερα |
| Αξιοποίηση % | Μισθωμένα χλμ / Συνολικά χλμ × 100 |
| Έσοδο ανά χλμ | Καθαρά έσοδα / Συνολικά χλμ |

- Η φόρμα **δεν έχει ημερομηνία**: κάθε βάρδια ανήκει σε **Μήνα / Έτος** (dropdown). Η επιλογή
  έτους/μήνα **θυμάται** σε κάθε συσκευή. Αν καταχωρείτε σε μήνα διαφορετικό από τον τρέχοντα,
  εμφανίζεται προειδοποίηση.
- Ο **Αριθμός Ζ** είναι υποχρεωτικός· αν ξαναδοθεί ίδιος Ζ για τον ίδιο οδηγό, η εφαρμογή ρωτάει.
- Τα αριθμητικά πεδία δέχονται ελληνικό κόμμα (`80,5`) ή τελεία (`80.5`).
- Τα ποσά υπολογίζονται σε ακέραια λεπτά — χωρίς σφάλματα δεκαδικών.
- **Διόρθωση βάρδιας**: «Επεξεργασία» στο ιστορικό ανοίγει τη βάρδια στη φόρμα (π.χ. για ξεχασμένα
  έξοδα)· ο ΦΠΑ και το ταμείο ξαναϋπολογίζονται από τη βάση.

## Επιπλέον

- **Γράφημα**: κάτω από τα στατιστικά, με 3 κουμπιά — **Τζίρος** (μικτή είσπραξη), **Διαδρομές** και
  **Μέση αξία διαδρομής** ((καθαρά + ΦΠΑ 13%) ÷ διαδρομές, χωρίς φιλοδωρήματα). Με συγκεκριμένο μήνα
  δείχνει μία τιμή ανά βάρδια (με σειρά αριθμού Ζ)· με «Όλοι οι μήνες» μία τιμή ανά μήνα του έτους.
  Με «Όλοι οι οδηγοί» κάθε οδηγός έχει δική του γραμμή, πάντα με το ίδιο χρώμα. Η διακεκομμένη γραμμή
  είναι ο μέσος όρος. Πατήστε ή αγγίξτε το γράφημα για τις τιμές· η «Προβολή πίνακα» δείχνει τα ίδια
  νούμερα σε πίνακα. Η επιλογή κουμπιού μένει αποθηκευμένη στη συσκευή.
- **Εξαγωγή Excel (CSV)**: κουμπί στην κορυφή· εξάγει ό,τι βλέπετε (περίοδος/οδηγός) σε UTF-8 με BOM,
  διαχωριστικό `;` και ελληνική υποδιαστολή, ώστε να ανοίγει σωστά στο ελληνικό Excel. Περιλαμβάνει
  γραμμή συνόλων και σύνοψη ΦΠΑ για τον λογιστή.
- **WhatsApp**: δίπλα στην κάρτα «Προς Απόδοση ΦΠΑ». Επιλέξτε οδηγό στο φίλτρο και πατήστε
  «Αποστολή WhatsApp»: ανοίγει `wa.me/30…` με έτοιμο κείμενο (όνομα, πινακίδα, μήνας, είσπραξη,
  έξοδα, ΦΠΑ και Χρεωστικό/Πιστωτικό).
- **Χωρίς σήμα**: αν πέσει το internet τη στιγμή της καταχώρησης, η βάρδια κρατιέται στη συσκευή
  και στέλνεται αυτόματα μόλις επανέλθει η σύνδεση (χωρίς κίνδυνο διπλοεγγραφής).
- **Μεταφορά από την παλιά τοπική έκδοση**: αν ανοίξετε την εφαρμογή στον ίδιο browser/διεύθυνση
  όπου τρέχατε την offline έκδοση, ο admin βλέπει κουμπί «Μεταφορά στο Supabase».

## Εγκατάσταση βήμα-βήμα

### 1. Supabase project

1. Στο [supabase.com](https://supabase.com) → **New project**. Προτείνεται **νέο, καθαρό project**
   (region: *Central EU (Frankfurt)*).
2. Κρατήστε τον κωδικό της βάσης κάπου ασφαλές (δεν χρειάζεται στην εφαρμογή).

> Αν θέλετε να κρατήσετε το **παλιό** project, δείτε πρώτα την ενότητα [Παλιό Supabase project](#παλιό-supabase-project).

### 2. Βάση δεδομένων

1. Supabase → **SQL Editor** → **New query**.
2. Επικολλήστε **ολόκληρο** το αρχείο
   [`supabase/migrations/20260927120000_taxi_fleet.sql`](supabase/migrations/20260927120000_taxi_fleet.sql)
   και πατήστε **Run**. Πρέπει να δείτε «Success. No rows returned».

Δημιουργούνται οι πίνακες `profiles`, `drivers`, `shifts`, η αναφορά `monthly_summary`
(σύνολα ανά οδηγό/μήνα, για χρήση και από το Table Editor) και όλοι οι κανόνες ασφαλείας.

> Εναλλακτικά με το CLI: `npx supabase login`, `npx supabase link --project-ref <ref>`, `npx supabase db push`.

### 3. Ρυθμίσεις Authentication

**Authentication → URL Configuration**

- **Site URL**: η διεύθυνση της εφαρμογής, π.χ. `https://taxi-fleet.vercel.app`
  (για δοκιμές στον υπολογιστή: `http://localhost:3000`).
- **Redirect URLs**: προσθέστε
  - `https://taxi-fleet.vercel.app/**`
  - `http://localhost:3000/**`

**Email** (σημαντικό): η δωρεάν υπηρεσία email του Supabase στέλνει email **μόνο** στα μέλη της
ομάδας του project και ελάχιστα την ώρα. Για να κάνουν οι οδηγοί μόνοι τους εγγραφή, ρυθμίστε δικό
σας SMTP στο **Authentication → Emails → SMTP Settings** (π.χ. Resend, Brevo ή Gmail με App Password).
Αν δεν θέλετε SMTP, δείτε την «Επιλογή Β» στο βήμα 7.

> Μην απενεργοποιήσετε το **Confirm email**: η επιβεβαίωση αποδεικνύει ότι το email ανήκει
> πράγματι στον οδηγό πριν δει τα στοιχεία του.

### 4. Σύνδεση της εφαρμογής με το Supabase

Το URL και το publishable key του project βρίσκονται ήδη μέσα στον κώδικα
([`lib/supabase/config.ts`](lib/supabase/config.ts)): είναι δημόσιες τιμές (τις λαμβάνει ο browser
κάθε επισκέπτη) και την ασφάλεια την κάνουν οι κανόνες RLS της βάσης. Άρα **δεν χρειάζονται
μεταβλητές περιβάλλοντος** ούτε `.env.local`.

Για **άλλο** Supabase project (ή τοπικό Supabase), αλλάξτε τις δύο τιμές στο αρχείο αυτό ή ορίστε
**και τις δύο** μεταβλητές (έχουν προτεραιότητα· δείτε το `.env.example`):

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Τιμές-παράδειγμα με `xxxx…` αγνοούνται. Σε παλαιότερα projects, αντί για publishable key μπορείτε να
βάλετε το **anon** key στη μεταβλητή `NEXT_PUBLIC_SUPABASE_ANON_KEY`. **Ποτέ** το `secret` /
`service_role` key — η εφαρμογή το αναγνωρίζει και αρνείται να ξεκινήσει.

### 5. Εκτέλεση στον υπολογιστή

Χρειάζεται Node.js 20.9+ (προτείνεται 22).

```bash
npm install
npm run dev
```

Ανοίξτε το http://localhost:3000. Αν κάτι λείπει (μεταβλητές, SQL), η εφαρμογή δείχνει οδηγίες
αντί για σφάλμα.

### 6. Πρώτη σύνδεση — Ιδιοκτήτης (Admin)

1. **Δημιουργία λογαριασμού** με το email σας → επιβεβαίωση από το email → σύνδεση.
2. Εμφανίζεται η οθόνη «δεν έχει αντιστοιχιστεί» με το κουμπί
   **«Είμαι ο ιδιοκτήτης — ενεργοποίηση ως Διαχειριστής»**. Πατήστε το.
   Γίνεται **μόνο μία φορά**: μόλις υπάρξει Admin, το κουμπί δεν εμφανίζεται σε κανέναν άλλον.
3. Στην **Υποδομή Στόλου** (κάτω) προσθέστε οδηγούς: Όνομα, Πινακίδα (π.χ. `ΤΑΕ-1234`),
   Κινητό (`69XXXXXXXX`) και προαιρετικά **Email σύνδεσης**. Αν οδηγείτε κι εσείς, προσθέστε και τον
   εαυτό σας με το δικό σας email.

### 7. Πρόσβαση οδηγών από το κινητό τους

Ο οδηγός συνδέεται **αυτόματα** με την εγγραφή του στον στόλο όταν το (επιβεβαιωμένο) email του
λογαριασμού του είναι ίδιο με το «Email σύνδεσης» που δηλώσατε.

- **Επιλογή Α — ο οδηγός κάνει εγγραφή μόνος του** (χρειάζεται SMTP, βήμα 3): δηλώστε το email του
  στην Υποδομή Στόλου και στείλτε του τον σύνδεσμο με το κουμπί **«Πρόσκληση»** (WhatsApp). Ο οδηγός
  ανοίγει `…/register`, επιβεβαιώνει το email και βλέπει αμέσως τις δικές του βάρδιες.
- **Επιλογή Β — δημιουργείτε εσείς τον λογαριασμό** (χωρίς SMTP): Supabase → **Authentication →
  Users → Add user → Create new user**, βάλτε email και κωδικό και τσεκάρετε **Auto Confirm User**.
  Δώστε στον οδηγό το email/κωδικό του.

Αν κάποιος οδηγός γραφτεί με διαφορετικό email, εμφανίζεται στην ενότητα **«Λογαριασμοί χωρίς
αντιστοίχιση»** της Υποδομής Στόλου και τον αντιστοιχίζετε με ένα κλικ. Για να κόψετε την πρόσβαση
ενός οδηγού: σβήστε το email του ή πατήστε **Απενεργοποίηση** (κρατά το ιστορικό του).

> Στο κινητό: άνοιγμα της σελίδας → μενού browser → **«Προσθήκη στην αρχική οθόνη»** για να ανοίγει σαν εφαρμογή.

### 8. Δημοσίευση στο Vercel

1. Συνδέστε το GitHub repository στο [vercel.com](https://vercel.com) → **Add New… → Project**.
2. **Deploy** — δεν χρειάζονται Environment Variables (βήμα 4). Κάθε νέο push στο GitHub κάνει
   αυτόματα νέο deploy.
3. Βάλτε τη διεύθυνση του Vercel στο Site URL / Redirect URLs (βήμα 3).
4. Αν ορίσετε μεταβλητές `NEXT_PUBLIC_…`, διαλέξτε τύπο **Config** (όχι Secret) και κάντε **Redeploy**:
   ενσωματώνονται στο build.

### 9. Δεδομένα από την παλιά τοπική (offline) έκδοση

Η παλιά έκδοση αποθήκευε τα πάντα στον browser (`localStorage`). Ανοίξτε τη νέα εφαρμογή **στον ίδιο
browser και στην ίδια διεύθυνση** (π.χ. `http://localhost:3000`), συνδεθείτε ως Admin και πατήστε
**«Μεταφορά στο Supabase»**. Οι οδηγοί αντιστοιχίζονται με το όνομα (οι νέοι δημιουργούνται
αυτόματα), ο ΦΠΑ υπολογίζεται ξανά από τη βάση και ένα αντίγραφο των παλιών δεδομένων μένει
στη συσκευή. Η μεταφορά μπορεί να ξανατρέξει χωρίς διπλοεγγραφές.

### Παλιό Supabase project

Το SQL σταματά με μήνυμα αν βρει ήδη πίνακες `profiles`, `drivers` ή `shifts`. Αν θέλετε να κρατήσετε
το παλιό project **χωρίς να χαθεί τίποτα**, μετακινήστε πρώτα τους παλιούς πίνακες σε ξεχωριστό schema
(μαζί με τα ευρετήριά τους, εκτός API) και μετά τρέξτε το SQL:

```sql
create schema if not exists old_backup;
revoke all on schema old_backup from public, anon, authenticated;
alter table if exists public.profiles set schema old_backup;
alter table if exists public.drivers  set schema old_backup;
alter table if exists public.shifts   set schema old_backup;
```

Μια απλή μετονομασία (`rename`) δεν αρκεί: τα ευρετήρια κρατούν τα παλιά ονόματα (π.χ. `profiles_pkey`)
και συγκρούονται με τα νέα.

Ελέγξτε επίσης για παλιά triggers στους λογαριασμούς (που μπορεί να γράφουν στους παλιούς πίνακες):

```sql
select tgname from pg_trigger where tgrelid = 'auth.users'::regclass and not tgisinternal;
```

Όσα δεν είναι `on_auth_user_created` / `on_auth_user_updated` διαγράψτε τα με
`drop trigger <όνομα> on auth.users;`. Οι υπάρχοντες λογαριασμοί διατηρούνται και ο ιδιοκτήτης
γίνεται Admin με το κουμπί του βήματος 6.

```
app/                     σελίδες (App Router): /, /login, /register, /forgot-password,
                         /update-password, /auth/callback
components/dashboard/    Dashboard, φόρμα βάρδιας, στατιστικά, ιστορικό, στόλος, ουρά αποστολής
lib/accounting.ts        λογιστικοί υπολογισμοί (σε λεπτά) — ίδιοι με τη βάση
lib/chart.ts             δεδομένα γραφήματος (ανά βάρδια / μήνα / οδηγό)
lib/csv.ts, whatsapp.ts  εξαγωγή Excel και μήνυμα WhatsApp
lib/supabase/            clients (browser/server) και ανανέωση συνεδρίας για τον proxy
proxy.ts                 ανανέωση συνεδρίας & ανακατεύθυνση στο /login (Next.js 16: πρώην middleware)
supabase/migrations/     σχήμα βάσης, υπολογιζόμενες στήλες, triggers, RLS
supabase/tests/          tests ασφαλείας/λογιστικής της βάσης (pgTAP)
```

| Εντολή | |
|---|---|
| `npm run dev` | εκτέλεση για ανάπτυξη |
| `npm test` | unit tests (λογιστική, γράφημα, CSV, WhatsApp, φόρμα, μεταφορά δεδομένων) |
| `npm run lint` / `npm run typecheck` | έλεγχοι κώδικα |
| `npm run build` | production build |
| `npm run db:start` | τοπικό Supabase (χρειάζεται Docker) |
| `npm run db:reset` | επαναδημιουργία τοπικής βάσης από τα migrations |
| `npm run db:test` | tests της βάσης: ποιος βλέπει τι, ΦΠΑ, triggers |
| `npm run db:types` | TypeScript τύποι από την τοπική βάση (`lib/database.types.ts`) |

Για τοπικό Supabase: `npm run db:start`, και στο `.env.local` βάλτε το `API_URL` και το
`PUBLISHABLE_KEY` που εμφανίζει η εντολή. Τα email επιβεβαίωσης φαίνονται στο Mailpit
(http://127.0.0.1:54324).
