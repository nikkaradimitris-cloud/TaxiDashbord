# 🚕 Taxi Fleet Tracker

Εφαρμογή για στόλο ταξί: καταχώρηση βαρδιών από το κινητό, αυτόματος υπολογισμός ΦΠΑ,
καθαρό ταμείο, στατιστικά απόδοσης, εξαγωγή σε Excel και ενημέρωση οδηγών μέσω WhatsApp.

> Βοηθητικό εργαλείο: δείχνει στον οδηγό πώς αποδίδει η δουλειά του και κρατά όλα τα οικονομικά του ταξί
> σε ένα μέρος. Τα ποσά είναι ενδεικτικά και δεν αντικαθιστούν τη δουλειά του λογιστή (`lib/disclaimer.ts`:
> το ίδιο κείμενο στην εφαρμογή).

- **Next.js 16** (App Router, TypeScript) — mobile-first: στο κινητό η φόρμα είναι πάνω από τα στατιστικά.
- **Supabase** — Authentication (email/κωδικός) και PostgreSQL με **Row Level Security**.
- **Χωριστοί στόλοι**: όποιος κάνει εγγραφή και πατήσει «Έχω δικό μου ταξί» φτιάχνει τον δικό του
  στόλο και γίνεται ο ιδιοκτήτης του. Κανείς δεν βλέπει τα στοιχεία άλλου στόλου.
- Δύο ρόλοι μέσα σε κάθε στόλο:

| | Admin (ιδιοκτήτης) | Οδηγός |
|---|---|---|
| Βάρδιες | όλων των οδηγών **του στόλου του** | **μόνο τις δικές του** |
| Καταχώρηση βάρδιας | για οποιονδήποτε οδηγό του στόλου του | μόνο για τον εαυτό του |
| Διόρθωση/διαγραφή βάρδιας | πάντα | μόνο δικές του, μέσα σε 24 ώρες |
| Στατιστικά / ΦΠΑ / Ταμείο | συνολικά & ανά οδηγό | μόνο των δικών του βαρδιών |
| Υποδομή Στόλου, WhatsApp | ✔ | ✘ |
| Εξαγωγή Excel (CSV) | ✔ (τα φιλτραρισμένα) | ✔ (μόνο τα δικά του) |
| Άλλοι στόλοι | ✘ | ✘ |

Η απομόνωση των δεδομένων γίνεται **μέσα στη βάση** (RLS): ισχύει ακόμη κι αν κάποιος καλέσει
απευθείας το API του Supabase με το δικό του λογαριασμό.

## Λογιστικοί κανόνες

Οι ίδιοι τύποι υπάρχουν στον κώδικα (`lib/accounting.ts`, για τη ζωντανή προεπισκόπηση της φόρμας)
και **μέσα στη βάση** ως υπολογιζόμενες στήλες των πινάκων `shifts`, `vehicle_expenses` και
`platform_statements` — η βάση είναι η πηγή της αλήθειας και ο ΦΠΑ δεν μπορεί να γραφτεί χειροκίνητα.

| Μέγεθος | Τύπος |
|---|---|
| ΦΠΑ εσόδων 13% | `round(Καθαρά × 0.129933, 2)` — π.χ. 160,39 € → **20,84 €** |
| **Ταμείο** (τζίρος) | Καθαρά + ΦΠΑ 13% + Φιλοδωρήματα/Άλλα έσοδα (χωρίς ΦΠΑ): ό,τι εισέπραξε το αυτοκίνητο, χωρίς καμία αφαίρεση |
| Σύνολο εξόδων | Καύσιμα των βαρδιών + Επισκευές / Συντήρηση (έξοδα οχήματος) + Κρατήσεις εφαρμογών του μήνα (τελικά ποσά)· τα «Άλλα έξοδα» όχι |
| ΦΠΑ εξόδων 24% (εμπεριεχόμενος) | `round(ποσό / 1.24 × 0.24, 2)` για καύσιμα, όλα τα έξοδα οχήματος (και τα «Άλλα έξοδα») και κρατήσεις με ΦΠΑ (π.χ. FreeNow)· οι κρατήσεις χωρίς ΦΠΑ (Uber, ενδοκοινοτικά) δεν συμψηφίζονται |
| Κράτηση εβδομάδας | Αυτόματα: ποσοστό × «Συνολικά έσοδα», + ΦΠΑ 24% όπου υπάρχει (π.χ. FreeNow 12% + ΦΠΑ, 99 € → 14,73 €)· ή η «Προμήθεια» του εγγράφου, αν γράφει άλλη. Ο ΦΠΑ 24% μέσα της βγαίνει αυτόματα — π.χ. 85,14 € → **16,48 €** |
| Κράτηση εφαρμογής (μήνα) | Το μηνιαίο τιμολόγιο όταν έχει καταχωρηθεί, αλλιώς το άθροισμα των εβδομάδων |
| Προς απόδοση ΦΠΑ | ΦΠΑ 13% − ΦΠΑ εξόδων 24% → θετικό = **Χρεωστικό**, αρνητικό = **Πιστωτικό** |
| **Καθαρό κέρδος** | Ταμείο − ΦΠΑ 13% − καθαρή αξία εξόδων (χωρίς ΦΠΑ)· ο ΦΠΑ των εξόδων συμψηφίζεται χωριστά με τον ΦΠΑ 13% (προς απόδοση). Τα «Άλλα έξοδα» δεν αφαιρούνται· ο ΦΠΑ τους μπαίνει στον συμψηφισμό και προστίθεται στο κέρδος. Π.χ. Ζ 912: 204,85 − 23,56 − 19,35 = 161,94 €, ΦΠΑ 23,56 − 4,65 = 18,91 € προς απόδοση (στη βάση, `net_cash` = ταμείο − έξοδα, χωρίς τον ΦΠΑ) |
| Διαδρομές από τον δρόμο | Διαδρομές των Ζ − Διαδρομές των εφαρμογών |
| Συνολικά χλμ | Μισθωμένα + Ελεύθερα |
| Αξιοποίηση % | Μισθωμένα χλμ / Συνολικά χλμ × 100 |
| Έσοδο ανά χλμ | Καθαρά έσοδα / Συνολικά χλμ |
| Επίπεδο αξιοποίησης | Βενζίνη, πετρέλαιο, αέριο: κάτω από 65% χαμηλή, 65–70% ικανοποιητική, από 70% πολύ ικανοποιητική· υβριδικό, ηλεκτρικό: 55% / 60%. Όλος ο στόλος: όρια ανάλογα με τα χλμ κάθε αυτοκινήτου (`lib/utilization.ts`) |

- Η φόρμα **δεν έχει ημερομηνία**: κάθε βάρδια ανήκει σε **Μήνα / Έτος** (dropdown). Η επιλογή
  έτους/μήνα **θυμάται** σε κάθε συσκευή. Αν καταχωρείτε σε μήνα διαφορετικό από τον τρέχοντα,
  εμφανίζεται προειδοποίηση.
- Ο **Αριθμός Ζ** είναι υποχρεωτικός· αν ξαναδοθεί ίδιος Ζ για τον ίδιο οδηγό, η εφαρμογή ρωτάει.
- Τα αριθμητικά πεδία δέχονται ελληνικό κόμμα (`80,5`) ή τελεία (`80.5`).
- Τα ποσά υπολογίζονται σε ακέραια λεπτά — χωρίς σφάλματα δεκαδικών.
- **Διόρθωση βάρδιας**: «Επεξεργασία» στο ιστορικό ανοίγει τη βάρδια στη φόρμα (π.χ. για ξεχασμένα
  καύσιμα)· ο ΦΠΑ και το ταμείο ξαναϋπολογίζονται από τη βάση.
- **Ιστορικό Βαρδιών**: με τη σειρά των Ζ ανά μήνα και αυτοκίνητο, το νεότερο πάνω (όχι με τη σειρά που
  γράφτηκαν: το 911 είναι πάντα ανάμεσα στο 910 και στο 912). Κάθε βάρδια δείχνει την πράξη:
  Καθαρά (χωρίς ΦΠΑ) + ΦΠΑ 13% + Φιλοδωρήματα = **Ταμείο** (με ΦΠΑ)· − ΦΠΑ 13% − Καύσιμα χωρίς ΦΠΑ = **Καθαρό
  κέρδος**· και χωριστά ο συμψηφισμός: ΦΠΑ 13% − ΦΠΑ καυσίμων = ΦΠΑ προς απόδοση.
- **Στη βάρδια μπαίνουν μόνο τα καύσιμα.** Επισκευές / συντήρηση και άλλα έξοδα του αυτοκινήτου είναι
  **«Έξοδο οχήματος»** (διακόπτης «Βάρδια | Έξοδο οχήματος» πάνω στη φόρμα): Μήνας/Έτος, αυτοκίνητο,
  είδος (**«Επισκευές / Συντήρηση»** ή **«Άλλα έξοδα»**), ποσό με ΦΠΑ 24%, περιγραφή. Ένα συνεργείο
  800 € δεν «χαλάει» το ταμείο μιας βάρδιας· μετράει στα έξοδα, στον ΦΠΑ (154,84 € συμψηφίζονται) και στο κέρδος του μήνα και του αυτοκινήτου.
  Από τα **«Άλλα έξοδα» μετράει μόνο ο ΦΠΑ** (συμψηφίζεται): το ποσό τους δεν μπαίνει στα «Συνολικά Έξοδα» και
  δεν αφαιρείται από το κέρδος (π.χ. 180 € → μόνο ο ΦΠΑ 34,84 €). Η φόρμα το γράφει κάτω από το είδος, η λίστα
  έχει σήμανση «μόνο ΦΠΑ» και χωριστό σύνολο, η «Ανάλυση ΦΠΑ» μια σημείωση και το Excel χωριστή γραμμή
  «Άλλα Έξοδα — μόνο ΦΠΑ» (στη βάση: στήλη `vat_only_expenses` της `monthly_summary`).
  Καταχωρούν ο ιδιοκτήτης (για κάθε αυτοκίνητο) και ο οδηγός (μόνο για το δικό του)· ο οδηγός
  διορθώνει/διαγράφει δικά του έξοδα μέσα σε 24 ώρες. Φαίνονται στη λίστα «Έξοδα Οχήματος», στα
  «Συνολικά Έξοδα» («καύσιμα · έξοδα οχήματος») και σε δική τους ενότητα στο Excel.
- **Εφαρμογές (Uber / FreeNow / Bolt)**: τρίτη επιλογή του διακόπτη, **«Εφαρμογή»**. Κάθε εβδομάδα ο
  οδηγός **αντιγράφει το έγγραφο** που στέλνει η εφαρμογή (FreeNow: «Σύνολο Διαδρομών», «Συνολικά
  Έσοδα», «Προμήθεια προς Freenow» χωρίς το μείον, «Λοιπές Επιστροφές / Επιβραβεύσεις» στα
  **Φιλοδωρήματα / Quest**)· στο τέλος του μήνα και το **τιμολόγιο** των κρατήσεων (με προαιρετικό αριθμό).
  - **Ποσοστό, μία φορά**: την πρώτη φορά που ο οδηγός διαλέγει μια εφαρμογή γράφει το ποσοστό της για
    το αυτοκίνητό του (χωρίς ΦΠΑ, π.χ. 12) και αν το τιμολόγιό της έχει ΦΠΑ 24% ή όχι (ενδοκοινοτικό)·
    το αλλάζει όποτε χρειαστεί («Αλλαγή»). Η **Uber** είναι πάντα χωρίς ΦΠΑ (κλειδωμένο, και στη
    βάση)· στη **Bolt** ο ΦΠΑ δεν έχει προεπιλογή και πρέπει να διαλεχτεί.
  - Το ποσοστό **υπολογίζει** την προμήθεια: μόλις γραφτούν τα «Συνολικά έσοδα», το πεδίο «Προμήθεια»
    συμπληρώνεται μόνο του (ποσοστό × έσοδα, + ΦΠΑ 24% όπου υπάρχει). Αν το έγγραφο γράφει άλλη, ο οδηγός
    γράφει εκείνη· το «Αυτόματα από το ποσοστό: … €» ξαναφέρνει τον υπολογισμό, και ένα σβησμένο πεδίο
    γυρίζει μόνο του στο αυτόματο. Αν η προμήθεια που γράφτηκε απέχει πολύ από ποσοστό × έσοδα (π.χ. άλλη
    γραμμή του εγγράφου), βγαίνει προειδοποίηση — η καταχώρηση γίνεται κανονικά. Λίγο κάτω είναι φυσικό: τα
    φιλοδωρήματα μέσα στα έσοδα δεν έχουν προμήθεια.
  - Τα **φιλοδωρήματα / quest** (χωρίς προμήθεια, έξω από τα έσοδα) δεν είναι μέσα στα Ζ: φαίνονται
    χωριστά και δεν μπαίνουν στον τζίρο δρόμου. Στη βάση, τζίρος = έσοδα + φιλοδωρήματα/quest (`tips`).
  - Η εβδομάδα είναι Δευτέρα–Κυριακή και **κόβεται στην αλλαγή του μήνα**: π.χ. ο Οκτώβριος 2026
    ξεκινά Πέμπτη, άρα οι εβδομάδες του είναι 1–4, 5–11, …, 26–31. Διαλέγεται από λίστα· η φόρμα
    προτείνει την επόμενη που λείπει και δεν δέχεται την ίδια εβδομάδα δύο φορές.
  - Οι κούρσες των εφαρμογών είναι μέσα στα Ζ: **διαδρομές δρόμου = Ζ − εφαρμογές** (κάρτα «Δρόμος &
    Εφαρμογές» στα στατιστικά, με έσοδα και κράτηση ανά εφαρμογή). Γι' αυτό τα έσοδα των εφαρμογών **δεν
    προστίθενται** στην είσπραξη (θα μετρούσαν δύο φορές): στα έξοδα και στο κέρδος μπαίνει μόνο η κράτηση.
  - Στα έξοδα, στον ΦΠΑ και στο κέρδος μετράει το **τιμολόγιο** του μήνα· μέχρι να καταχωρηθεί,
    μετράνε οι εβδομάδες («προσωρινή» κράτηση). Ο ΦΠΑ 24% της κράτησης συμψηφίζεται· οι κρατήσεις
    χωρίς ΦΠΑ (Uber) μετράνε στα έξοδα αλλά όχι στον συμψηφισμό.
  - Η λίστα «Εφαρμογές» δείχνει για κάθε αυτοκίνητο και μήνα ποιες εβδομάδες έχουν μπει (✓), ποιες
    λείπουν και αν υπάρχει τιμολόγιο (με τη διαφορά από τις εβδομάδες). Πάτημα σε εβδομάδα που λείπει (κόκκινη)
    ή που τρέχει (γκρι) ανοίγει τη φόρμα «Εφαρμογή» με αυτή την εφαρμογή και εβδομάδα.
  - **«Δουλεύει με»** (πάνω στη λίστα, για ένα αυτοκίνητο): ο ιδιοκτήτης ή ο οδηγός πατά τις εφαρμογές που
    δουλεύει το αυτοκίνητο (`platform_rates.active`). Για όσες είναι «εκτός» δεν ζητούνται εβδομάδες (ούτε
    μηδενικά) και δεν φαίνονται στη φόρμα· το ποσοστό τους μένει για όταν ξαναμπούν. Εφαρμογή χωρίς ποσοστό
    ανοίγει τη φόρμα, που το ζητά μία φορά. Δικαιώματα όπως στα έξοδα
    οχήματος· δική τους ενότητα στο Excel· κρατήσεις και διαδρομές δρόμου μέσα στο «Έσοδα, χιλιόμετρα &
    διαδρομές» (ενότητα «Δρόμος & Εφαρμογές»).

## Επιπλέον

- **Εικονίδιο στο κινητό**: «Εγκατάσταση» (Android: κουμπί στην κεντρική σελίδα και στο «Καλώς ήρθατε»·
  iPhone: «Κοινοποίηση» → «Προσθήκη στην οθόνη Αφετηρίας»). Ανοίγει σε πλήρη οθόνη χωρίς τη γραμμή του
  browser. Αν ανοίξει χωρίς σήμα, δείχνει τη σελίδα «Χωρίς σύνδεση» (service worker, χωρίς να κρατά
  στοιχεία). Τα PNG των εικονιδίων βγαίνουν από τα SVG με `node scripts/icons.mjs`.
- **Κίνηση ανοίγματος**: μία φορά σε κάθε άνοιγμα της εφαρμογής, όσο φορτώνουν τα στοιχεία· ένα πάτημα
  την κλείνει. Την πρώτη φορά μόνο το λογότυπο (μετά έρχεται το «Καλώς ήρθατε»)· από εκεί και πέρα κάθε
  άνοιγμα δείχνει άλλη διαδρομή στον χάρτη και μία άλλη δυνατότητα της εφαρμογής, πρώτο τον ΦΠΑ του
  μήνα (`components/intro/scenes.ts`).
- **«Καλώς ήρθατε»**: πέντε κάρτες με κινούμενα σχέδια: για τον οδηγό (ό,τι φαίνεται αμέσως από το Ζ),
  αξιοποίηση χιλιομέτρων, ΦΠΑ στο τέλος του μήνα (από Ζ, έξοδα και τιμολόγια εφαρμογών), γιατί
  φτιάχτηκε. Το ταμείο δεν «υπόσχεται» να φαίνεται αμέσως: βγαίνει σωστό όταν μπουν και τα τιμολόγια
  των εφαρμογών. Βγαίνει μόνη της την πρώτη φορά σε κάθε συσκευή και ξανά από το
  «Τι κάνει η εφαρμογή» (σύνδεση και κάτω κάτω στην κεντρική). Με «μείωση κίνησης» στο κινητό όλα μένουν
  ακίνητα.
- **Αναλυτικά (Πίνακας / Γράφημα)**: κάτω από τα στατιστικά. Ανοίγει ως **πίνακας** με **Τζίρο**
  (μικτή είσπραξη), **Διαδρομές** και **Μέση αξία διαδρομής** ((καθαρά + ΦΠΑ 13%) ÷ διαδρομές, χωρίς
  φιλοδωρήματα), με σύνολο και μέσο όρο.
  - «Ανά βάρδια»: μία γραμμή ανά βάρδια (σειρά αριθμού Ζ, χωρισμένες ανά οδηγό).
  - «Ανά μήνα»: μία γραμμή για κάθε μήνα του έτους και σύνολο έτους· πατώντας έναν μήνα ανοίγουν οι
    βάρδιές του.
  - «Γράφημα»: κουμπιά Τζίρος / Διαδρομές / Μέση αξία διαδρομής· με «Όλοι οι οδηγοί» κάθε οδηγός έχει
    δική του γραμμή με σταθερό χρώμα, και η διακεκομμένη γραμμή είναι ο μέσος όρος. Πατήστε ή αγγίξτε
    το γράφημα για τις τιμές.

  Η συσκευή θυμάται την τελευταία επιλογή (πίνακας/γράφημα, ανά βάρδια/μήνα, κουμπί γραφήματος).
- **Μεγάλα γράμματα**: όλη η εφαρμογή έχει μεγαλύτερα, πιο ευανάγνωστα γράμματα. Με το κουμπί **«Α+»**
  (πάνω δεξιά, και στη σελίδα σύνδεσης) μεγαλώνουν ακόμη περισσότερο· η συσκευή το θυμάται.
- **Εξαγωγή Excel (CSV)**: κουμπί στην κορυφή· εξάγει ό,τι βλέπετε (περίοδος/οδηγός) σε UTF-8 με BOM,
  διαχωριστικό `;` και ελληνική υποδιαστολή, ώστε να ανοίγει σωστά στο ελληνικό Excel. Περιλαμβάνει
  γραμμή συνόλων και σύνοψη ΦΠΑ για τον λογιστή.
- **Αξιοποίηση χιλιομέτρων**: σκούρα κάρτα με κυκλικό μετρητή (όπως στο «Καλώς ήρθατε») μέσα στα
  στατιστικά, μετά τα ποσά: μισθωμένα / συνολικά χλμ, έσοδο ανά χλμ, επίπεδο με χρώμα (κόκκινο =
  χαμηλή, με προτροπή για περισσότερα μισθωμένα χλμ· γαλάζιο = ικανοποιητική· πράσινο = πολύ
  ικανοποιητική) και κλίμακα σύγκρισης. Τα όρια εξαρτώνται από το **καύσιμο** του αυτοκινήτου
  (`drivers.fuel`): διαλέγεται στο «Έχω δικό μου ταξί» (υποχρεωτικό) και στην «Υποδομή Στόλου»· για
  αυτοκίνητα χωρίς καύσιμο ο ιδιοκτήτης το διαλέγει μία φορά μέσα στην κάρτα (μέχρι τότε ισχύουν τα
  όρια βενζίνης/πετρελαίου/αερίου).
- **WhatsApp**: δίπλα στην κάρτα «Προς Απόδοση ΦΠΑ» (οδηγός στο φίλτρο, ή το μόνο αυτοκίνητο του
  στόλου). Στέλνει **μόνο τον ΦΠΑ**: εικόνα 1080×1080 στο ίδιο σκούρο στυλ (περίοδος, αυτοκίνητο, ΦΠΑ
  εσόδων/εξόδων, ποσό, Χρεωστικό/Πιστωτικό, «Ενδεικτικός υπολογισμός») και σύντομο μήνυμα. Στο κινητό
  ανοίγει το μενού κοινοποίησης (WhatsApp → παραλήπτης)· στον υπολογιστή ανοίγει `wa.me/30…` με το
  μήνυμα και η εικόνα κατεβαίνει με το «Λήψη εικόνας».
- **Στείλτε την εφαρμογή σε φίλο** (κάτω, μόνο ο ιδιοκτήτης): ανοίγει το WhatsApp με έτοιμο μήνυμα και
  τον σύνδεσμο της εφαρμογής· το WhatsApp δείχνει την εικόνα προεπισκόπησης `app/opengraph-image.png`
  (πηγή: `scripts/share-image.svg`, ξαναφτιάχνεται με `node scripts/icons.mjs`).
- **Χωρίς σήμα**: αν πέσει το internet τη στιγμή της καταχώρησης, η βάρδια κρατιέται στη συσκευή
  και στέλνεται αυτόματα μόλις επανέλθει η σύνδεση (χωρίς κίνδυνο διπλοεγγραφής).
- **Μεταφορά από την παλιά τοπική έκδοση**: αν ανοίξετε την εφαρμογή στον ίδιο browser/διεύθυνση
  όπου τρέχατε την offline έκδοση, ο admin βλέπει κουμπί «Μεταφορά στο Supabase».
- **Αντίγραφο ασφαλείας** (μόνο ο admin): πάνελ στο τέλος της σελίδας· κατεβάζει όλους τους πίνακες
  σε ένα αρχείο Excel `taxi-fleet-antigrafo-ΕΕΕΕ-ΜΜ-ΗΗ.xlsx`, μία καρτέλα για κάθε είδος (βάρδιες,
  έξοδα οχήματος, εφαρμογές, ποσοστά, οδηγοί, λογαριασμοί) με ελληνικούς τίτλους, ονόματα αντί για
  κωδικούς και ποσά σε ευρώ· στο τέλος κάθε καρτέλας οι στήλες της βάσης για την επαναφορά. Στο δωρεάν
  πακέτο η Supabase δεν δίνει αντίγραφα για κατέβασμα, γι' αυτό η εφαρμογή το θυμίζει πάνω στη σελίδα
  όταν έχουν περάσει 30 μέρες. Η ημερομηνία του τελευταίου αντιγράφου μένει στον λογαριασμό (user
  metadata), ίδια σε κινητό και υπολογιστή. Το αρχείο πάει στις «Λήψεις» και στο κινητό ανοίγει με
  Excel ή «Υπολογιστικά φύλλα Google» (χωρίς αυτά φαίνεται με λευκό εικονίδιο και δεν ανοίγει· γι' αυτό
  το πάνελ έχει, πριν από το κατέβασμα, κουμπιά Google Play και App Store για την εφαρμογή). Γράφεται όπως τα γράφει το ίδιο το Excel (κείμενα στο `sharedStrings`, ιδιότητες
  εγγράφου), γιατί κάποιες εφαρμογές δεν διαβάζουν κείμενα γραμμένα μέσα στο κελί.
- **«Λείπει Ζ»** (μόνο ο admin): τα Ζ κάθε οδηγού είναι συνεχόμενα· κάθε οδηγός ελέγχεται χωριστά,
  και όταν μοιράζεται αυτοκίνητο (έχει δικά του φορολογικά στοιχεία). Αν λείπει Ζ ανάμεσα σε δύο
  καταχωρημένα (π.χ. 5, 6, 8 → λείπει το Ζ 7), το «Ιστορικό Βαρδιών» το γράφει στον τίτλο και μέσα. Όχι
  για Ζ πριν από το πρώτο ή μετά το τελευταίο της περιόδου· πολύ μεγάλο κενό (πάνω από 31) εμφανίζεται
  ως «μήπως γράφτηκε λάθος ο αριθμός».

## Εγκατάσταση βήμα-βήμα

### 1. Supabase project

1. Στο [supabase.com](https://supabase.com) → **New project**. Προτείνεται **νέο, καθαρό project**
   (region: *Central EU (Frankfurt)*).
2. Κρατήστε τον κωδικό της βάσης κάπου ασφαλές (δεν χρειάζεται στην εφαρμογή).

> Αν θέλετε να κρατήσετε το **παλιό** project, δείτε πρώτα την ενότητα [Παλιό Supabase project](#παλιό-supabase-project).

### 2. Βάση δεδομένων

1. Supabase → **SQL Editor** → **New query**.
2. Επικολλήστε **ολόκληρο** κάθε αρχείο του φακέλου `supabase/migrations`, **με τη σειρά**, και πατήστε
   **Run** για το καθένα (πρέπει να δείτε «Success. No rows returned»):
   1. [`20260927120000_taxi_fleet.sql`](supabase/migrations/20260927120000_taxi_fleet.sql) — πίνακες, κανόνες ασφαλείας
   2. [`20260927160000_shift_editing.sql`](supabase/migrations/20260927160000_shift_editing.sql) — διόρθωση βαρδιών
   3. [`20260928090000_vehicle_expenses.sql`](supabase/migrations/20260928090000_vehicle_expenses.sql) — έξοδα οχήματος
   4. [`20260928140000_platform_statements.sql`](supabase/migrations/20260928140000_platform_statements.sql) — εφαρμογές (Uber / FreeNow / Bolt)
   5. [`20260929090000_fleets.sql`](supabase/migrations/20260929090000_fleets.sql) — χωριστοί στόλοι, προσκλήσεις οδηγών
      (τα στοιχεία που υπάρχουν ήδη γίνονται ο στόλος του υπάρχοντος Admin)

Δημιουργούνται οι πίνακες `profiles`, `fleets`, `drivers`, `shifts`, `vehicle_expenses`, `platform_rates`, `platform_statements`,
η αναφορά `monthly_summary` (σύνολα ανά αυτοκίνητο/μήνα, μαζί με τα έξοδα οχήματος, τις κρατήσεις
και τις διαδρομές δρόμου / εφαρμογών, για χρήση και από το Table Editor) και όλοι οι κανόνες ασφαλείας.

> Εναλλακτικά με το CLI: `npx supabase login`, `npx supabase link --project-ref <ref>`, `npx supabase db push`.

### 3. Ρυθμίσεις Authentication

**Authentication → URL Configuration**

- **Site URL**: η διεύθυνση της εφαρμογής, π.χ. `https://taxi-fleet.vercel.app`
  (για δοκιμές στον υπολογιστή: `http://localhost:3000`).
- **Redirect URLs**: προσθέστε
  - `https://taxi-fleet.vercel.app/**`
  - `http://localhost:3000/**`

**Email** (σημαντικό): η δωρεάν υπηρεσία email του Supabase στέλνει email **μόνο** στα μέλη της
ομάδας του project και ελάχιστα την ώρα. Για να κάνουν οι οδηγοί μόνοι τους εγγραφή, ρυθμίστε δικό
σας SMTP στο **Authentication → Emails → SMTP Settings** (π.χ. Resend, Brevo ή Gmail με App Password).
Αν δεν θέλετε SMTP, δείτε την «Επιλογή Β» στο βήμα 7.

> Μην απενεργοποιήσετε το **Confirm email**: η επιβεβαίωση αποδεικνύει ότι το email ανήκει
> πράγματι στον οδηγό πριν δει τα στοιχεία του.

### 4. Σύνδεση της εφαρμογής με το Supabase

Το URL και το publishable key του project βρίσκονται ήδη μέσα στον κώδικα
([`lib/supabase/config.ts`](lib/supabase/config.ts)): είναι δημόσιες τιμές (τις λαμβάνει ο browser
κάθε επισκέπτη) και την ασφάλεια την κάνουν οι κανόνες RLS της βάσης. Άρα **δεν χρειάζονται
μεταβλητές περιβάλλοντος** ούτε `.env.local`.

Για **άλλο** Supabase project (ή τοπικό Supabase), αλλάξτε τις δύο τιμές στο αρχείο αυτό ή ορίστε
**και τις δύο** μεταβλητές (έχουν προτεραιότητα· δείτε το `.env.example`):

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Τιμές-παράδειγμα με `xxxx…` αγνοούνται. Σε παλαιότερα projects, αντί για publishable key μπορείτε να
βάλετε το **anon** key στη μεταβλητή `NEXT_PUBLIC_SUPABASE_ANON_KEY`. **Ποτέ** το `secret` /
`service_role` key — η εφαρμογή το αναγνωρίζει και αρνείται να ξεκινήσει.

### 5. Εκτέλεση στον υπολογιστή

Χρειάζεται Node.js 20.9+ (προτείνεται 22).

```bash
npm install
npm run dev
```

Ανοίξτε το http://localhost:3000. Αν κάτι λείπει (μεταβλητές, SQL), η εφαρμογή δείχνει οδηγίες
αντί για σφάλμα.

### 6. Πρώτη σύνδεση — Ιδιοκτήτης (Admin)

1. **Δημιουργία λογαριασμού** με το email σας → επιβεβαίωση από το email → σύνδεση.
2. Πατήστε **«Έχω δικό μου ταξί»**, γράψτε το όνομά σας και την πινακίδα και πατήστε **«Δημιουργία»**.
   Φτιάχνεται ο στόλος σας με το ταξί σας (συνδεδεμένο με τον λογαριασμό σας) και γίνεστε ο Admin του.
   Το ίδιο κάνει κάθε φίλος με δικό του ταξί: ο καθένας έχει τον δικό του στόλο και βλέπει μόνο αυτόν.
3. Στην **Υποδομή Στόλου** (κάτω) προσθέστε οδηγούς: Όνομα, Πινακίδα (π.χ. `ΤΑΕ-1234`),
   Κινητό (`69XXXXXXXX`) και προαιρετικά **Email σύνδεσης**.

### 7. Πρόσβαση οδηγών από το κινητό τους

Ο οδηγός κάνει εγγραφή με το email που δηλώσατε ως «Email σύνδεσης» και, αφού το επιβεβαιώσει, βλέπει
την **πρόσκληση** (ποιος στόλος, ποιο αυτοκίνητο). Μπαίνει στον στόλο μόνο όταν πατήσει **«Αποδοχή»**:
κανένας στόλος δεν «τραβάει» λογαριασμό χωρίς τη συγκατάθεσή του. Κάθε λογαριασμός ανήκει σε έναν στόλο.

- **Επιλογή Α — ο οδηγός κάνει εγγραφή μόνος του** (χρειάζεται SMTP, βήμα 3): δηλώστε το email του
  στην Υποδομή Στόλου και στείλτε του τον σύνδεσμο με το κουμπί **«Πρόσκληση»** (WhatsApp). Ο οδηγός
  ανοίγει `…/register`, επιβεβαιώνει το email, πατά «Αποδοχή» και βλέπει τις δικές του βάρδιες.
- **Επιλογή Β — δημιουργείτε εσείς τον λογαριασμό** (χωρίς SMTP): Supabase → **Authentication →
  Users → Add user → Create new user**, βάλτε email και κωδικό και τσεκάρετε **Auto Confirm User**.
  Δώστε στον οδηγό το email/κωδικό του· με την πρώτη σύνδεση πατά «Αποδοχή».

Ο ιδιοκτήτης δεν βλέπει ποιοι έκαναν εγγραφή στην εφαρμογή (μπορεί να είναι άλλων στόλων). Αν κάποιος
οδηγός γραφτεί με διαφορετικό email, γράψτε αυτό το email στην **Επεξεργασία** του οδηγού και ο οδηγός
πατά «Ανανέωση» και «Αποδοχή». Για να κόψετε την πρόσβαση ενός οδηγού: σβήστε το email του ή πατήστε
**Απενεργοποίηση** (κρατά το ιστορικό του).

> Στο κινητό: άνοιγμα της σελίδας → μενού browser → **«Προσθήκη στην αρχική οθόνη»** για να ανοίγει σαν εφαρμογή.

### 8. Δημοσίευση στο Vercel

1. Συνδέστε το GitHub repository στο [vercel.com](https://vercel.com) → **Add New… → Project**.
2. **Deploy** — δεν χρειάζονται Environment Variables (βήμα 4). Κάθε νέο push στο GitHub κάνει
   αυτόματα νέο deploy.
3. Βάλτε τη διεύθυνση του Vercel στο Site URL / Redirect URLs (βήμα 3).
4. Αν ορίσετε μεταβλητές `NEXT_PUBLIC_…`, διαλέξτε τύπο **Config** (όχι Secret) και κάντε **Redeploy**:
   ενσωματώνονται στο build.

### 9. Δεδομένα από την παλιά τοπική (offline) έκδοση

Η παλιά έκδοση αποθήκευε τα πάντα στον browser (`localStorage`). Ανοίξτε τη νέα εφαρμογή **στον ίδιο
browser και στην ίδια διεύθυνση** (π.χ. `http://localhost:3000`), συνδεθείτε ως Admin και πατήστε
**«Μεταφορά στο Supabase»**. Οι οδηγοί αντιστοιχίζονται με το όνομα (οι νέοι δημιουργούνται
αυτόματα), ο ΦΠΑ υπολογίζεται ξανά από τη βάση και ένα αντίγραφο των παλιών δεδομένων μένει
στη συσκευή. Η μεταφορά μπορεί να ξανατρέξει χωρίς διπλοεγγραφές.

### Παλιό Supabase project

Το SQL σταματά με μήνυμα αν βρει ήδη πίνακες `profiles`, `drivers` ή `shifts`. Αν θέλετε να κρατήσετε
το παλιό project **χωρίς να χαθεί τίποτα**, μετακινήστε πρώτα τους παλιούς πίνακες σε ξεχωριστό schema
(μαζί με τα ευρετήριά τους, εκτός API) και μετά τρέξτε το SQL:

```sql
create schema if not exists old_backup;
revoke all on schema old_backup from public, anon, authenticated;
alter table if exists public.profiles set schema old_backup;
alter table if exists public.drivers  set schema old_backup;
alter table if exists public.shifts   set schema old_backup;
```

Μια απλή μετονομασία (`rename`) δεν αρκεί: τα ευρετήρια κρατούν τα παλιά ονόματα (π.χ. `profiles_pkey`)
και συγκρούονται με τα νέα.

Ελέγξτε επίσης για παλιά triggers στους λογαριασμούς (που μπορεί να γράφουν στους παλιούς πίνακες):

```sql
select tgname from pg_trigger where tgrelid = 'auth.users'::regclass and not tgisinternal;
```

Όσα δεν είναι `on_auth_user_created` / `on_auth_user_updated` διαγράψτε τα με
`drop trigger <όνομα> on auth.users;`. Οι υπάρχοντες λογαριασμοί διατηρούνται και ο ιδιοκτήτης
γίνεται Admin με το κουμπί του βήματος 6.
